# Contexto do Projeto: Sonda de Cartografia Semântica (IARA / Projeto Fauna)

**Estado Atual:** Nosso motor em Rust não é mais um gerador de texto tradicional. Ele é um **Híbrido Neuromórfico** rodando em tempo contínuo. Substituímos a inferência estática por uma rede de Equações Diferenciais (CfC do MIT), onde as matrizes $Q, K, V$ do Qwen 3 (8B) modulam a amplitude e o $\tau$ (tau) dos neurônios. Adicionamos a Sincronia de Kuramoto para acoplamento de fase, permitindo que múltiplos "seres" (prompts) coexistam e interfiram em um grid de ativação (Digital Fauna).

**O Problema Atual:** O painel de observabilidade (mapa de calor) mostra a rede vibrando e se sincronizando perfeitamente. No entanto, estamos "cegos" para a geografia do que está vibrando. Precisamos de Interpretabilidade Mecanística. Queremos mapear o "cérebro" do Qwen para entender como ele abstrai conceitos. Se o modelo tem a memória do que é uma "casa" ou um "carro", queremos achar exatamente onde essa abstração vive e quem são seus vizinhos, para guiar a ressonância da nossa LNN.

---

## 🎯 Objetivo da Tarefa

Projete a arquitetura e escreva o código base em Rust para um **Módulo de Cartografia Semântica (Sonda)**. Este utilitário rodará em paralelo ao motor principal e servirá para mapear o espaço vetorial estático da LLM, criando um grafo de relacionamentos.

### 1. Requisitos do Backend (Rust)
* **Leitura do Dicionário:** Carregar o `tokenizer.json` para mapear IDs numéricos para strings (palavras/tokens).
* **Extração Direta:** Usar `safetensors` e `memmap2` para extrair APENAS a matriz da camada inicial de embeddings (geralmente `model.embed_tokens.weight`) do Qwen 8B. Ignorar o resto do modelo para poupar RAM.
* **Motor de Busca Semântica:** Implementar uma função matemática de Similaridade de Cossenos hiper-otimizada (usando `rayon` para paralelismo, se necessário):
  $$\text{Similaridade} = \frac{A \cdot B}{||A|| \times ||B||}$$
* **O Fluxo:** Dado um token de entrada (ex: "carro" ou "casa"), o sistema localiza seu ID, pega seu vetor de $N$ dimensões (ex: 4096 floats), e varre os 151.936 tokens do Qwen para encontrar os top 50 "vizinhos" mais próximos geometricamente.

### 2. Integração e Saída de Dados
* Estruturar a saída dessa busca em um formato de Grafo (Nós e Arestas) usando `serde_json`.
* Cada Nó deve conter o Token (string) e o "peso/distância" em relação ao conceito central.
* Este JSON deve ser servido via WebSocket ou endpoint REST rápido (`axum` ou similar) para o nosso painel de controle.

### 3. Requisitos do Frontend (Visão Geral)
* Sugira a melhor abordagem/biblioteca em JavaScript (ex: `3d-force-graph`, `Three.js` ou `D3.js`) para consumir esse JSON e renderizar uma constelação 3D interativa no navegador, onde o conceito pesquisado fica no centro e seus vizinhos orbitam ao redor ligados por fios.
